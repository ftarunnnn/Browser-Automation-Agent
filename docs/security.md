# WebPilot AI — Security Architecture & Policy

WebPilot AI adheres to strict safety and security principles to prevent unauthorized browser operations and protect user environment.

---

## 1. Human-in-the-Loop (HITL) Safety Policy

The agent evaluates every browser action before execution:
- **Low-Risk Actions** (Executed automatically):
  - Navigating to public URLs (`open_url`)
  - Scrolling pages (`scroll`)
  - Reading text & extracting content (`extract_text`, `extract_links`)
  - Taking screen captures (`screenshot`)
- **Sensitive Operations** (Require explicit user confirmation via UI modal):
  - Making purchases or financial payments (`buy`, `checkout`, `pay`)
  - Submitting registration or order forms (`submit`, `register`)
  - Sending emails or messages (`send email`, `post comment`)
  - Deleting data or account settings (`delete`, `remove`, `drop`)

---

## 2. Anti-Bypass & Access Controls

- **CAPTCHA & MFA**: WebPilot AI **never** attempts to bypass CAPTCHA, MFA, or website access restrictions.
- **Manual Authentication**: Users manually authenticate when login credentials are required.
- **No Password Logging**: Sensitive password fields are automatically sanitized and never stored in logs or database tables.

---

## 3. Input Validation & Protection

- **SSRF Protection**: `InputValidator` blocks access to `file://`, `gopher://`, `dict://`, and internal loopback addresses (`127.0.0.1`, `localhost`, `169.254.169.254`).
- **Path Traversal Protection**: File download names are sanitized to prevent directory traversal (`../../etc/passwd`).
- **No Code Execution**: The LLM engine is restricted to structured JSON tool parameters. WebPilot AI **never** executes arbitrary Python or JavaScript code generated by AI models.
